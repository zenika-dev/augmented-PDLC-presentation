Spec-Driven Development and What It Does to Context

A Spec-Driven Development framework moves AI from generating code to working inside a maintained context, guided by explicit, verifiable specifications.

A shared context
One place to gather and share what the organisation knows.
Specs as witnesses
They turn business, technical and functional intent into increments an agent can take in and a human can check.
The system keeps learning
Documentation is never frozen: it grows with every delivery.
Humans provide the intent
Agents observe, check and produce, but never decide.

The contract

A Level of Delegation

Criteria specific to each task decide how much of it the machine may take. Example: the code assistant capability, with illustrative scores.

The score · 86
An agent scores the task out of 100: unit test coverage 24/30, complexity 22/25, domain criticality 25/25, static-analysis issues 15/20. At 86 the task could run AI-autonomous.
Blocking rule · 79 at most
Generated code always goes through a merge request and the CI. That caps the level at the top of AI-executed.
Foundation ceiling · 65
The maturity of each foundation sets a ceiling on every capability. Here the foundations hold it at 65: the most restrictive limit wins.
Result · AI-executed, human in the loop
The agent does the work; a human checks each result before it applies. This is where a pilot starts.
Next level · human on the loop
Once the foundations mature and automated gates with sampled reviews replace the per-change rule, the task reaches AI-autonomous. The human sets the contract, watches the dials and steps in on exceptions.

How Do We Choose the Best Model at the Right Time?

First iterations
Spec received → capability used, model picked by hand in the in-house chat assistant or another tool → performance indicator · new Spec or other artefact → fed back into the context
Following iterations
Spec received → capability used → best model proposed from the context → performance indicator · new Spec or other artefact → fed back into the context
Every quarter: a benchmark
An evaluation set drawn from your own capabilities runs against the current models. The gateway's default for each capability changes on that evidence, for quality and for cost.
